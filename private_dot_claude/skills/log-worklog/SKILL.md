# Work Log 記録（Obsidian 連携）

このセッション（呼び出し元のプロジェクトが何であれ）で実際に行った作業を，Obsidian vault の今日の日次 Work Log に追記する．
振り返りの文章を新しく考えるのではなく，**このセッションで実際にやったことをそのまま書き写す**．解釈・要約・評価を加えない．

- Vault: `~/Documents/m1sk9-vault`
- 対象ファイル: `06_Work/Logs/<対象日 YYYY-MM-DD>.md`（引数なしなら今日）
- テンプレート: `00_Templates/worklogs.md`

## 動作モード

- **通常モード**（日付引数なし）: このセッションで行った作業を今日のログに転記する．
- **遡及モード**（日付引数あり）: ログを書き忘れた日について，その日の作業を記録から集計して書き込む．引数は `YYYY-MM-DD`，`昨日`，`一昨日`，`yesterday` のいずれか．引数の残りは補足として扱う．

## 手順

### 1. 対象日と対象ファイルを確定する

`date +%Y-%m-%d` で今日の日付を得る．遡及モードなら引数から対象日を決める（相対表現は今日を基準に解決する）．対象は `~/Documents/m1sk9-vault/06_Work/Logs/<対象日>.md`．

遡及モードでは次を確認する:

- 対象日が未来なら中止して報告する．
- 対象日が**前週以前**（今日を含む週の月曜より前）なら，書き込む前に必ずユーザーへ「<対象日> は前週です．記録してよいですか」と確認し，明確な承認を得てから進める．今週内の過去日は確認不要．週報は前週分を集約する運用なので，提出済みの週報と食い違う可能性があることも確認時に添える．

### 2. 作業内容を洗い出す

通常モードでは，このセッション内で実際に行ったことを列挙する（会話を遡って確認する．推測で埋めない）．

遡及モードでは，対象日の作業を次の記録から集める．いずれも実在する記録に基づき，推測で埋めない．記録が見つからなければ，その旨を報告して書き込まずに止まる．

- Claude Code のセッション記録: `~/.claude/projects/**/*.jsonl` のうち対象日の `timestamp` を持つ行（ファイルの mtime は日跨ぎで外れるため，行の timestamp で絞る）．
- `gh search prs --author @me --updated <対象日>` などで得た，対象日に更新された自分の PR．
- 主要リポジトリの `git log --author <自分> --since <対象日> --until <翌日>`．

- 触れた GitHub PR の URL（`https://github.com/<owner>/<repo>/pull/<number>` 形式）
- PR ごとに，実際に行った変更・レビュー対応・マージ等の内容
- PR に紐づかない作業（調査，設定変更，ツール移行判断など）
- ユーザーから引数として補足が渡されていれば，それも書き加える内容に含める

遡及モードでは，集計結果を書き込む前に一覧（PR とその他作業）をユーザーへ提示し，過不足がないか確認する．

### 3. 対象ファイルの現状を読む

`rg` または Read で対象ファイルを読む．

- ファイルが存在しない場合は，`00_Templates/worklogs.md` と同じ構成（front matter + `## PR 処理` / `## その他作業` / `## 懸念・問題点` / `## 引き継ぎ (月〜木)` / `## 来週への引き継ぎ`）で新規作成する．front matter の `created` / `updated` は現在時刻（`YYYY-MM-DDTHH:mm:ss`）にする．
- 遡及モードで新規作成する場合も，front matter の `created` / `updated` は対象日ではなく実際の作成時刻にする．
- 既に存在する場合は，既存の内容・書き方（タブインデント，PR は URL 見出し＋インデント箇条書き）を壊さずに追記する．

### 4. 振り分けて追記する

- GitHub PR の URL が関わる内容 → `## PR 処理` に追記する．
  - 同じ PR の URL が既にその日のログにあれば，その項目の下に箇条書きを追加する（同じ PR で新しい見出しを作らない）．
  - 新しい PR なら `- <PR URL>:` を追加し，その下にタブインデントで内容を書く．
- PR に紐づかない作業 → `## その他作業` に追記する．
- 既存ログの文体（簡潔な日本語，体言止め・用言止め混在，技術的な固有名詞はそのまま）に合わせる．敬体にしない．

### 5. 書き込む

- **書き込みは Obsidian MCP のファイル作成／書き込みツールを使う**（vault の CLAUDE.md 規則: Obsidian への書き込みは MCP）．
- MCP が当該セッションで利用不可の場合のみ，`~/Documents/m1sk9-vault/06_Work/Logs/<日付>.md` へ Write でフォールバックする（その旨を必ず報告する．Obsidian アプリと Local REST API プラグインが起動していないと MCP は繋がらない）．
- `## 懸念・問題点` や引き継ぎ系セクションなど，今回の作業に関係ないセクションは触らない．

### 6. 報告する

書き込んだ内容（追記した箇条書き）と対象ファイルのパスを，最後に短く提示する．黙って書きっぱなしにしない．
